# 技术目录与阶段预测

## 技术目录

技术管理采用固定最多三级的主目录：

```text
智能建造
├── 工程软件
├── 工程物联网
├── 构件智能生产
├── 智能施工机械
└── 工程大数据与互联网平台
```

数据集只能绑定有效启用的三级技术，项目只能绑定有效启用的一级技术。技术节点使用稳定
`node_id`；移动节点不会改变 ID。主界面只展示目录结构和数据覆盖，关键词/别名位于高级
匹配设置，稳定 ID、关系、引用和变更记录位于高级治理。

已有数据集、项目或任务引用的节点只能停用，不能物理删除。节点只有在自身及全部祖先均
启用时才“有效启用”；停用父节点会让后代继承停用，但不覆盖后代自身状态和历史快照。
数字孪生、大模型等跨域关系继续保留，不复制树节点。

## 阶段数据

基础数据对外只分为 IPC、论文、综合数据三类，并必须选择以下阶段之一：

| 阶段代码 | 年份范围 |
|---|---|
| `2010_2015` | 2010-2015 |
| `2016_2020` | 2016-2020 |
| `2021_2026` | 2021-2026 |

IPC 数据内部可包含指标表和融合关系表。论文数据可包含元数据表或论文文档。
综合数据是独立的多文件容器，发布前至少包含一个有效 IPC 组成和一个有效论文
组成，综合分析报告为可选组成。

结构化记录年份必须落在所选阶段。论文文档不能识别年份时需要人工填写。

## 项目与预测节点

新项目选择一级技术和目标年份，以2026为基线：

| 目标年份 | 累计预测节点 |
|---|---|
| 2030 | 2030 |
| 2035 | 2030、2035 |
| 2040 | 2030、2035、2040 |

任务启动时冻结一级技术路径、全部有效三级后代、目录版本、阶段分析、证据包和
累计节点。历史2025基线任务继续按原快照读取。

## 阶段分析

系统使用确定性代码计算：

- IPC 总量、年均量、CAGR、斜率、中心度、变化点和融合强度。
- 论文总量、年均量、关键词新增、持续、消退和代表论文。
- IPC 与论文方向的收敛、互补、冲突或证据不足。

不同长度阶段使用年均量和每年增长指标比较，同时保留原始总量。所有新任务的
数据截止年份为2026，晚于2026的数据不会进入上下文。

## 迁移与回滚

默认先执行 dry-run：

```bash
python3 scripts/migrate_taxonomy_stage_data.py
```

确认报告后执行：

```bash
python3 scripts/migrate_taxonomy_stage_data.py --apply
```

报告位于 `var/migration/taxonomy-stage-migration.json`。无法确定技术的旧数据
标记为 `needs_mapping`，跨阶段数据标记为 `needs_split`。迁移不删除数据集、
项目、任务和上传文件。这些未完成映射的数据不会进入新的项目证据检索。

可在迁移前运行以下只读盘点：

```bash
python3 scripts/inventory_workflow_data.py \
  --output var/migration/streamlined-workflow-inventory.json
```

回滚前停止服务，并恢复同一备份批次的 `var/library/`、`var/projects/` 和
`var/jobs/`。
