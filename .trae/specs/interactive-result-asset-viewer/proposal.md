# 结果资产查看器与技术发展详情 - 变更提案

## Overview
- **Change Name**: `interactive-result-asset-viewer`
- **Summary**: 将技术预测工作台的结果页改造为“结果总览 + 技术主题目录 + 点击式资产预览 + 技术发展详情”的管理台式界面。后端负责生成并保存 PNG/PDF 等图表资产与路线数据，前端只通过受控 API 按需读取和展示，不在后端报告页面直接嵌入图片。
- **Purpose**: 解决当前结果页将 ECharts 图表和文本一次性平铺、后端已有的高质量图表没有进入任务资产目录、路线图缺少可点击详情入口的问题，使研究人员能在结果页中逐主题审阅技术发展证据。
- **Target Users**: 智能建造技术预测研究人员、行业分析人员、技术战略规划人员。

## Background
现有系统已能够在 `src/report/roadmap_charts.py` 生成单主题的：
- 综合分析图（TRL、里程碑、不确定性等）。
- 时间轴甘特图。
- 技术特征雷达图。
- 全主题综合比较图。

但工作台任务目前只生成 `charts.json` 中的 ECharts 数据，未将 PNG 图表作为 job 级资产收集与提供；前端将结果图表直接展示在页面，缺少可点击的主题详情、图表预览和技术发展阶段说明。

## Goals
- 后端为每个预测 job 生成或收集独立的图表资产，并保存到 `data/workbench/jobs/<job_id>/assets/`。
- 提供资产目录、资产文件、主题技术发展详情的 API，避免将本地输出目录直接暴露给浏览器。
- 前端结果页采用“概览统计卡片 + 技术主题列表 + 筛选 + 主题行操作”的管理台层级，风格参考示例图的侧栏、顶栏、统计卡片、标签页和表格密度。
- 图表与技术发展内容均由用户点击进入预览抽屉或模态框，不在结果首页一次性堆叠。
- 支持查看各主题在 `2025` 基线、`2030`、`2035`、`2040` 节点的阶段说明、里程碑、TRL、不确定性、依赖和证据。
- 支持从资产预览下载单个 PNG 图表，并保留 JSON/Markdown 整体导出。

## Non-Goals
- 不重新生成或改变现有预测模型、路线图 prompt、TRL 算法。
- 不将图片二进制写入 `result.json` 或 base64 返回给前端。
- 不实现复杂的在线图片编辑、标注协作或权限系统。
- 不将用户给出的界面示例中的 Hostplatform 业务语义引入本项目。

## Proposed User Flow
```text
预测完成
  │
  ▼
结果概览页：统计卡片、主题数量、图表数量、置信度、不确定性
  │
  ├── 点击“技术发展” → 打开主题详情抽屉
  │      ├── 2025 基线
  │      ├── 2030 关键突破
  │      ├── 2035 系统集成
  │      └── 2040 成熟愿景
  │
  └── 点击“查看图表” → 打开资产预览模态框
         ├── 综合分析图
         ├── 时间轴路线图
         └── 技术雷达图
```

## Success Criteria
- 每个成功预测 job 的结果资产目录中包含主题级图表清单；单个图表缺失时不会中断其余资产生成。
- 前端可以通过 API 获取资产清单与图片 URL，并在点击后显示预览。
- 首页不直接渲染全尺寸 PNG 或全部路线图详情。
- 技术主题列表可以按主题名、预测节点、TRL 和不确定性筛选。
- 用户可以从一个主题详情中看到 2030、2035、2040 的里程碑与其关联的图表。
- 现有 `/results`、`/charts`、`/export` API 保持兼容。

## Risks
- Matplotlib 图表生成耗时可能增加预测任务结束时间，需要记录单张图生成失败原因并允许部分成功。
- 路线图主题名称包含中文或特殊字符，资产 ID 与文件名必须分离。
- 直接暴露任意文件路径会带来路径穿越风险，图片访问必须通过已登记的 `asset_id`。
- 主题较多时图片列表和详情载入应按需请求，避免一次下载所有大图。

## Open Questions
- 是否在首版提供跨主题综合图的独立预览入口？
- 资产是否只保留 PNG，还是同时保留高分辨率 PDF 导出？
- 是否需要在预览抽屉中支持主题之间的前后切换？
