## Why

现有工作台已经能生成 2030、2035、2040 三个节点的预测与路线图，但基础数据仍是固定 JSON 和样例摘要，文件输入、项目隔离、论文与 IPC 时序检索、证据版本化均不完整；证据在多轮预测中还会逐步丢失。需要将现有脚本式数据资源升级为可管理、可检索、可复现的研究证据体系，使预测结论真正建立在 IPC 趋势和论文研究方向的共同支撑上。

## What Changes

- 整理项目资源边界，将种子数据、运行数据、预测产物、研究文档和工具资源分开管理，停止跟踪日志与可再生产物。
- 新增基础数据中心，支持导入 IPC 时间序列表、IPC 融合关系表、论文元数据表以及 PDF、DOCX、TXT、Markdown 论文文件。
- 使用 SQLite 和 FTS5 管理数据集、文献、IPC 指标、融合关系、解析状态和版本信息，原始文件继续保存在受控本地目录。
- 将“本次预测输入材料”与“长期基础证据库”分离，支持文本粘贴和文件上传两种输入方式。
- 从本次材料提取关键信息和候选技术主题，并支持主题新增、编辑、删除、合并、归档及最终确认。
- 启动预测前，针对每个确认主题分别检索 IPC 趋势和论文证据，形成可人工审阅、可冻结的证据包。
- 修改预测编排，使证据包贯穿主题预测、范式归纳、全局路线图和分主题路线图，不再只在第一轮使用证据。
- 为预测阶段增加质量门槛：证据不足时警告或阻止启动；Round 1 为空时任务失败，不再生成空的正常结果。
- 扩展结果页面，展示 IPC 趋势、论文方向、证据收敛/冲突、2030/2035/2040 路线图、TRL、不确定性和引用追溯。
- 保持现有固定种子数据和 CLI 流程兼容，通过迁移适配层逐步切换到新数据中心。

## Capabilities

### New Capabilities

- `project-resource-governance`: 定义种子数据、运行状态、预测产物、研究文档和工具资源的目录边界、Git 跟踪策略及迁移规则。
- `evidence-data-library`: 管理 IPC 时序、融合关系、论文文件和论文元数据的导入、校验、去重、版本化、检索与统计。
- `research-material-ingestion`: 支持本次预测项目的文本输入和文件上传，解析关键信息并生成带来源证据的候选技术主题。
- `project-topic-calibration`: 在独立预测项目内新增、编辑、删除、合并、归档和确认主题，避免不同项目的主题互相污染。
- `topic-evidence-retrieval`: 按确认主题同时检索 IPC 和论文证据，支持人工取舍，并生成不可变、可复现的证据快照。
- `evidence-grounded-forecasting`: 将证据快照贯穿现有多轮预测与路线图生成，并对证据完整性和阶段产物实施质量门槛。
- `academic-forecast-visualization`: 可视化 IPC 趋势、论文方向、证据冲突、融合演化和 2030/2035/2040 技术路线，并提供结论到证据的追溯。

### Modified Capabilities

无。当前 `openspec/specs/` 中尚无已登记的基线 capability；本变更通过新增规范覆盖现有工作台的增量行为。

## Impact

- **后端**：新增 `src/ingestion/`、`src/library/`、`src/retrieval/`，重构 `src/api/` 的存储、项目、材料、主题和预测接口，并扩展 prompt builder 与预测编排器。
- **前端**：将当前单文件工作台拆为基础数据、预测项目、材料输入、主题校准、证据审阅、任务运行和结果分析页面。
- **数据**：引入 SQLite/FTS5；新增 `var/library/`、`var/projects/`、`var/jobs/`、`var/exports/`，保留 `data/seed/` 作为可跟踪演示数据。
- **依赖**：增加文件上传、XLSX、PDF、DOCX 解析依赖；不引入外部数据库服务或向量数据库。
- **兼容性**：现有 `topics.json`、`high_potential_pairs.json`、样例摘要和 CLI 入口继续可用，并提供一次性种子数据迁移。
- **安全与运维**：上传文件实施类型、大小、路径和内容校验；`.env`、日志、运行产物和本地索引不得进入版本控制。
